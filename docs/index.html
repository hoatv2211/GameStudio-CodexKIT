The trust contract

Trust is a data model, not a tone of voice.

Every meaningful claim carries a label. The kit makes it structurally difficult for an agent to turn missing evidence into a confident success report.

Verified

An observed command, test, build, primary source, or artifact supports the claim.

Snapshot

True for a named commit, version, configuration, or environment snapshot.

Unverified

A hypothesis or forecast that still needs evidence before it becomes a result.

BLOCKED

A runner, dependency, permission, live project, or required proof is unavailable.

CORE RULE · BLOCKED is never converted into PASS.
How a task moves

From vague failure
to bounded action.

A small request can still touch a large, fragile system. The workflow keeps discovery, mutation, ownership, and proof in the right order.

01 / INTAKE

Read the room

Capture the goal, project snapshot, risk tier, ownership, constraints, and do-not-touch paths.

02 / ROUTE

Pick the smallest skill

Route the natural-language request to one focused diagnostic, gate, or production workflow.

03 / ACT

Mutate with gates

Keep read-only work automatic. Escalate medium and high-risk changes with scope, backup, review, or approval.

04 / VERIFY

Return proof or blocker

Attach commands, exit codes, artifacts, limitations, and the honest verdict — including BLOCKED.
